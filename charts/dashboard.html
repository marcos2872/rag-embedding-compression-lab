Guia de Leitura — Variantes e Níveis de Bits

glossário

Variantes de Quantização

baseline_f32 referência
Embeddings originais em float32 (32 bits por valor). Nenhuma compressão aplicada. Serve como teto de qualidade: todos os resultados são comparados contra este baseline.
1 vetor × dim × 4 bytes = 1536 B (dim=384)
baseline_f16 compressão simples
Float16 (meia precisão): divide cada valor de 32 bits para 16 bits simplesmente reduzindo a precisão numérica. Sem transformação do vetor. Compressão de 2× com perda mínima de qualidade.
1 vetor × dim × 2 bytes = 768 B
uniform baseline quantização
Quantização escalar uniforme: divide o intervalo [min, max] de todos os valores em 2bits − 1 bins de largura igual, e armazena o índice de cada bin. Não aplica rotação. Método mais simples, serve como baseline para comparar com os métodos mais avançados.
bins uniformes • sem rotação • dados-dependente (min/max global)
lloyd_max codebook ótimo
Codebook Lloyd-Max: em vez de bins uniformes, calcula os 2bits centroides que minimizam o MSE para a distribuição teórica das coordenadas de um vetor unitário em Sd-1 (distribuição Beta concentrada em torno de zero). Não aplica rotação, por isso o codebook funciona mal sem ela — a distribuição real não corresponde à teórica.
bins ótimos (Lloyd-Max) • sem rotação • dados-independente
turbo_mse TurboQuant MSE
TurboQuantMSE (paper TurboQuant): aplica uma rotação ortogonal aleatória ao vetor antes de quantizar. A rotação equaliza a energia entre todas as dimensões, fazendo com que cada coordenada siga exatamente a distribuição teórica do codebook Lloyd-Max. Resultado: mesmo codebook, qualidade muito superior ao lloyd_max puro.
rotação Q + codebook Lloyd-Max • dados-independente • reconstrução: QT × dequant(idx)
turbo_prod TurboQuant Prod
TurboQuantProd: extensão do MSE que adiciona um segundo passo de compressão do resíduo usando QJL (Johnson-Lindenstrauss Quantizado). Usa (b-1) bits para a parte MSE e 1 bit por dimensão para o resíduo (sinal de uma projeção gaussiana). Elimina o viés de produto interno que o TurboQuantMSE introduz, produzindo estimativas de similaridade mais precisas.
rotação Q + Lloyd-Max(b-1 bits) + QJL resíduo(1 bit) • viés ≈ 0

Níveis de Bits — O que significa cada valor

32
Float32 (baseline)
Representação padrão de ponto flutuante (IEEE 754). 1536 bytes/vetor para dim=384. Precisão total, sem nenhuma compressão. Baseline de referência.
16
Float16 (baseline)
Meia precisão. 768 bytes/vetor (2× menor). Trunca mantissa de 23 para 10 bits. Perda de qualidade mínima. Compressão trivial sem algoritmo especial.
8
8-bit quantizado
256 níveis possíveis por dimensão. 386 bytes/vetor (4× menor). Qualidade próxima do float32 para todos os métodos. Ponto de entrada conservador para produção.
4
4-bit quantizado
16 níveis possíveis por dimensão. 194 bytes/vetor (8× menor). Sweet spot do paper TurboQuant: TurboQuantMSE 4-bit mantém qualidade igual ao float32 com 8× menos memória.
2
2-bit quantizado
4 níveis possíveis por dimensão. 98 bytes/vetor (16× menor). Compressão extrema: uniform 2-bit colapsa (Recall@10 cai >40pp). TurboQuantMSE aguenta com perda <2pp graças à rotação ortogonal.

⚡ Impacto prático
Use esta tabela como referência rápida para escolher a variante ideal para o seu caso de uso. Procure linhas com alta compressão E alto Recall@10.

Recall@10 vs Bits — Quanto a qualidade cai ao comprimir?

insight chave
📌 O que mostra
Mostra como o Recall@10 de cada variante varia conforme reduzimos o número de bits de 8 para 2. As linhas tracejadas marcam os baselines float32 e float16.
🔍 Como ler
Eixo X: bits por dimensão (8→4→2). Eixo Y: Recall@10 (0 = nenhum resultado correto, 1 = todos corretos). Linhas mais altas = melhor qualidade para o mesmo nível de compressão. Passe o mouse sobre os pontos para ver os valores exatos.
⚡ Impacto prático
TurboQuantMSE a 4-bit mantém Recall@10 igual ou superior ao float32 com 8× menos memória — o sweet spot do paper TurboQuant. Uniform a 2-bit colapsa: a rotação aleatória antes da quantização é o que diferencia os métodos.

Trade-off: Qualidade × Memória — O gráfico mais importante

mais importante
📌 O que mostra
Scatter plot onde cada ponto é uma configuração (variante + bits). Mostra simultaneamente a qualidade de retrieval e o custo de memória. A linha laranja é a fronteira de Pareto: pontos onde não é possível melhorar qualidade sem aumentar memória.
🔍 Como ler
Eixo X (log): quanto menor, mais economia de memória. Eixo Y: Recall@10 — quanto maior, melhor. O ponto ideal está no canto superior esquerdo. Pontos na fronteira de Pareto são as melhores escolhas possíveis. Passe o mouse para ver a taxa de compressão exata.
⚡ Impacto prático
Pontos TurboQuantMSE ficam acima de Uniform e Lloyd-Max para a mesma posição horizontal, provando que a rotação ortogonal é essencial. turbo_mse 4-bit é o sweet spot: 7.9× compressão sem perda de qualidade.

MSE por Variante — Distorção Geométrica dos Vetores

distorção geométrica
📌 O que mostra
Mede o erro quadrático médio (MSE) entre os vetores originais float32 e os vetores reconstruídos após quantização + dequantização. Indica o quanto a geometria do espaço de embeddings é distorcida.
🔍 Como ler
Eixo Y em escala log: valores menores = menos distorção. Cada grupo de barras representa um nível de bits (8→4→2). Barras mais baixas dentro do mesmo grupo = variante mais fiel ao original. Hover para ver o valor exato.
⚡ Impacto prático
Lloyd-Max sem rotação tem MSE alto apesar de usar o mesmo codebook que TurboQuantMSE. Isso confirma que o codebook ótimo sozinho não basta — a rotação é necessária para que a distribuição das coordenadas corresponda ao codebook teórico.

Heatmap de Erros de Produto Interno

viés de produto interno
📌 O que mostra
Mede três tipos de erro no produto interno (dot product) entre queries e documentos: IP Bias (viés sistemático), IP MAE (magnitude média do erro) e IP Variance (consistência do erro).
🔍 Como ler
Verde = erro baixo (bom). Vermelho = erro alto (ruim). Cada coluna é uma variante+bits. As células mostram o valor real. O IP Bias é especialmente importante: um viés alto significa que os scores de similaridade são sistematicamente errados.
⚡ Impacto prático
Lloyd-Max tem IP Bias altíssimo (−0.13 a 8-bit) pois o codebook recorta coordenadas grandes, criando viés. TurboQuantMSE elimina esse viés com a rotação. TurboQuantProd vai além: o QJL corrige o viés residual do MSE, mantendo IP Bias próximo de zero em todos os bits.

Compressão × Perda de Recall — Identificando o Sweet Spot

decisão de produção
📌 O que mostra
Gráfico dual-axis: as barras mostram a taxa de compressão de memória (quanto menor o embedding, maior a barra); a linha mostra a queda no Recall@10 em pontos percentuais em relação ao baseline float32.
🔍 Como ler
Barras altas = muita compressão (bom). Linha próxima de zero = pouca perda de qualidade (bom). O sweet spot é onde a barra é alta E a linha está perto de zero. Anotações em vermelho destacam quedas severas (>5pp).
⚡ Impacto prático
Qualquer variante com queda < 1pp e compressão > 7× é um candidato viável para produção. Compressão agressiva (2-bit) sem rotação causa quedas de 40+ pp — inutilizável. Com rotação (TurboQuantMSE 2-bit), a queda é < 2pp.
